# 极光紫：一篇用来检验排版的样张

排版这件事，读者说不出所以然，却一眼能分辨好坏：**行高太挤会累**、*字重太轻会飘*、`行内代码` 与正文混在一起会乱。这篇样张把常见 Markdown 元素排在一起，用来检查 `meetup-aurora` 这套皮肤的呼吸感。

## 一、标题层级与段落节奏

三级、四级标题在同一篇文章里不常出现，但一旦出现，字号阶梯必须清楚，否则读者会失去位置感。

### 1.1 三级标题的份量

正文用它来分段。段与段之间留出足够的空隙，长文才不至于糊成一片；标题与正文之间同理，标题压得太近会显得急躁。

#### 1.1.1 四级标题作为最小单位

四级标题通常只用于附录、参数说明这类细碎的内容。它比正文重一点，但不该抢走三级标题的注意力。

## 二、行内元素

- **加粗**用于结论和关键术语，一篇里出现三五次就够。
- *斜体*在中文里更多是语气上的轻读，英文书名、外文词汇也常用。
- `inline code` 用来标出字段名、命令、文件名，比如 `mdTheme: "dev-linear"`。
- ~~删除线~~表示「此说法已作废」，慎用：读者容易误读成否定。
- 链接的样式最容易被忽略：[源站样式参考](https://markdown.com.cn/wechat/) 的链接色与正文色同族，靠下划线区分，不刺眼。
- 脚注用来放补充说明，不打断正文节奏[^note]。

## 三、引用与提示框

> 普通引用只做视觉退让：左侧一条竖线，底色比正文浅一档，字号不变。适合放原文摘录、他人观点。

> [!NOTE] 说明
> 蓝色系提示框，语气中性。适合放前置条件、约定、名词解释。

> [!TIP] 小技巧
> 绿色系，适合操作建议。比如：调色时先改 `--md-accent`，再看整体是否协调。

> [!IMPORTANT] 重点
> 紫色系，用来强调结论。一篇长文里最好只用一次，多了就失去重点。

> [!WARNING] 注意
> 琥珀色系，用于风险提醒。比如：覆盖 `dooz.override.css` 时不要整段复制，容易带进旧规则。

> [!CAUTION] 警告
> 红色系，最高级别。用于不可逆操作，例如批量删除、强制推送。

## 四、列表形态

无序列表适合并列项：

- 主题色、背景色、边框色属于同一族
- 表头底色要略深于斑马纹
- 代码块底色不与页面底色撞色

有序列表适合步骤：

1. 在 front matter 写 `mdTheme`。
2. 确认站点没有用 `markdownTheme` 强行覆盖。
3. 本地 `hugo server` 看一遍长文与表格。

嵌套时缩进要收窄，避免层级过深：

- 一级：视觉变量
  - 二级：结构变量
    - 三级：极少用到，样式上仍需可读
- 一级：语义变量

任务清单用来表达进度：

- [x] 标题阶梯与正文行高
- [x] 表格、代码块、提示框
- [ ] 脚注与图片说明
- [ ] 移动端窄屏复查

定义列表适合术语表：

主题色
: 标题、链接、强调共用的那一支颜色。

中性色
: 正文、边框、底色所用的灰阶，决定整体冷暖。

## 五、表格

三线表最考验细节：表头字重、单元格内边距、数字对齐。

| 元素 | 默认取值 | 说明 |
| :--- | :--- | ---: |
| 正文行高 | 1.8 | 长文可再放宽 |
| 表头字重 | 600 | 与正文区分 |
| 单元格内边距 | 8px 12px | 窄屏可收窄 |
| 代码字号 | 13px | 略小于正文 |

## 六、代码块

```js
// 主题切换的最小实现：只改 data 属性，CSS 变量自动跟随
const article = document.querySelector(".md-body");
article.dataset.mdTheme = "dev-tech-blue";

// 数字与字符串在代码主题里各有颜色，注意别互相吃掉
const themes = ["editorial-sspai", "dev-linear", "plain-github"];
console.log(`已切换 ${themes.length} 套主题`);
```

命令行片段也要能读：

```bash
hugo server --themesDir ../../ --disableFastRender
```
